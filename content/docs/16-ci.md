The check is what keeps a fraktul true. Run it locally while you edit the model, and in CI so a code change that breaks
the fraktul fails its pull request.

```bash
fraktul check
```

## What fails

The check exits with an error when the model points at something that isn't there:

- a file that moved, was renamed or deleted, or isn't tracked by git;
- a function that was renamed or removed, or a `functions` entry with no `#name`;
- a decision record that doesn't exist;
- a block id that isn't lowercase letters, digits and `_`, or a block with no title;
- a `block/inner` box, an `@link` target or an `@expand` block that's gone;
- a tour step whose view, focus box, expanded block, narration cue or next step is missing, or a step id used twice;
- a repo name that isn't in `repos:`, or a stated remote fraktul can't link to;
- an `expect` promise the fraktul no longer keeps.

## What it lists

These don't fail the check unless you pass `--strict`:

- files that match `coverage:` but that the model doesn't mention yet;
- decision records no block mentions;
- with a [traces](/docs/traces) summary: calls between services that no diagram draws, and services no block claims.

It also prints blocks no diagram shows (reachable only from tours or panels), the drill-down depth of each top-level
block, and repos it skipped because they aren't checked out.

## Flags

| Flag | Does |
|---|---|
| `--strict` | Also fail on unmentioned files and decision records, and on calls and services the traces show that the fraktul does not. |
| `--json` | Print the report as JSON: `errors`, `unmentioned`, `traces`, `skipped`, `unreachable`, `stats`. |

Exit codes: `0` when everything resolves, `1` when something is broken, `2` when there is no model file.

## GitHub Actions

With fraktul in the project's `devDependencies`, the workflow installs and runs it like any other tool. The lockfile
pins its version, so a new fraktul release never surprises your CI.

```yaml
name: Map
on: [pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with: { node-version: 24, cache: npm }
      - run: npm ci
      - run: npx fraktul check
```

A project without a `package.json` can run `npx fraktul@0.1.0 check` instead: name the version, for the same reason.

> [!NOTE]
> Repos that aren't checked out on the runner are skipped and named in the output, so the job still verifies
> everything in the project itself. To check them too, check them out in the workflow and point fraktul at them with
> `FRAKTUL_REPO_<KEY>`, for example `FRAKTUL_REPO_BILLING: ${{ github.workspace }}/billing`.

## Keeping the fraktul current

- Run `fraktul check --strict` before a release, or always in CI once coverage is clean.
- When a file moves, fix the anchor in the same pull request. The check names the block and the path.
- Use `expect:` to keep tours and depth from being removed by accident.
