You don't have to write the model by hand. The model is a plain text file, and a check says when it is wrong, so an
AI coding assistant can write it.

This is how most people use fraktul: the assistant writes the map, the check keeps it honest, and you review the
part only a person can judge.

## Install the skill

fraktul ships an **agent skill**: instructions that teach an assistant how to map a system with fraktul. It works
with any assistant that reads skills from `.claude/skills` or `.agents/skills`: Claude Code, GitHub Copilot, Cursor,
Codex and Gemini CLI among them.

```bash
npm install --save-dev fraktul
npx fraktul skill
```

`fraktul skill` copies the skill into `.claude/skills/fraktul` and `.agents/skills/fraktul`. Commit both folders so
the whole team's assistants have it. `fraktul init` installs it too, unless you pass `--no-skill`. Run
`npx fraktul skill` again after upgrading fraktul to get the skill that matches.

## Ask for a map

Then ask, in your own words:

```text
Map this system with fraktul.
```

The assistant will:

1. Run `fraktul init` if there is no model yet.
2. Read the README, the entry points, the routes and the deploy files.
3. Write the levels, from the system down to the features, with a plain-language summary on every block.
4. Run `fraktul check`, fix what it reports, and repeat until every reference resolves.
5. Write a first tour: the path a new teammate should walk.

More to ask for, once the first map exists:

```text
Add a level under checkout: its features, one block each.
Write a tour that follows one order from the browser to the bank, for someone non-technical.
fraktul check --strict lists 14 unmapped files. Put each in the block it belongs to.
Pull the traces from our Jaeger and draw the calls the map is missing.
```

## What to review

The check proves every file, function and tour step in the model exists. It cannot prove the words are true. Read
these yourself:

- **The summaries.** Is each one what you would say to a new teammate? An assistant describes what code does; you
  know what it is for.
- **The arrows.** Does the top-level diagram show the flow you would draw on a whiteboard?
- **What was left out.** A good map has five to nine boxes per level. Ask what the assistant chose not to show.

Ask the assistant to list what it guessed. The skill tells it to.

## Keep it current

A map written once goes stale like any diagram. Make updating it part of every change:

- **Tell your assistant, once.** Add a line to `AGENTS.md` or `CLAUDE.md`:

```text
This project has a fraktul map (docs/arch/model.yaml). When you add, move or rename code,
update the model in the same change and run `npx fraktul check` before you finish.
```

- **Let CI catch what was missed.** Run [the check in CI](/docs/ci). A moved file then fails the pull request, and
  the fix is one line the assistant can write.

See [Keeping the map true](/docs/keeping-it-true) for the whole strategy.
