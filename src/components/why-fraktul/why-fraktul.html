Why it exists

Writing software got easy. Understanding it didn't.

I built fraktul because I kept ending up in the same meeting. Someone is leaving a project and has an hour to hand over three years of decisions. Or I'm the architect at the whiteboard, drawing the same boxes for the fourth team this quarter. Or I've been handed a service somebody else wrote, and I need to understand it by Friday, well enough to build the next one beside it.

Each time the knowledge was real, and it lived in one person's head and in a diagram that had stopped being true months before.

Then AI started writing most of the code.

A week now produces more code than anyone on the team has read. Code is no longer the scarce thing. A shared, correct picture of the system is: what the parts are, why they exist, and where a change has to land.

fraktul is the tool I wanted in those rooms. A person draws the picture. The code fills in everything below it. A check fails the build when the two stop agreeing. And the walkthrough is told once, in a real voice, so the next person presses play and nobody books another hour.

The maker of fraktul, Rinsesoft

    Learning someone else's system

    Start from the whole and click down until you reach a line of source. Who calls whom is read from the code, so it is never out of date.

    Keeping up with what AI writes

    New modules show up as not mapped yet, and a moved file breaks the check. The picture in your head and the code in the repo stay the same thing.
